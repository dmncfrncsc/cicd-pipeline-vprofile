### Recorded run evidence and conclusion

- **GitHub Actions — reported:** Build and Test #267 for PR #130 and #268 for a push to `main` are recorded as passing; raw event summaries were not opened. Three deployment dispatches are recorded as normal success, forced failure followed by same-app rollback, and a later successful deployment (`PROGRESS-HISTORY.md:517-520,808`).
- **Jenkins - reported:** Fifth- through eighth-test build and boot evidence is summarized in the dated history. For the ninth test, Build #1 stopped at the input check; Build #2 succeeded with the forced-failure switch off; Build #3 passed nine Maven tests and deployment health checks, deliberately failed, and ran rescue. Its Ansible recap reported `failed=1 rescued=1`; the restored app answered `/` and `/users`, and the database check reported 10 users. Builds #2 and #3 used the same WAR, so a distinct-release rollback is not demonstrated. The pipeline ended in FAILURE by design. This is one author-reported boot, not a fresh Jenkins check; see the [ninth-test history checkpoint](../PROGRESS-HISTORY.md).
- **Local Maven log — file evidence:** `build-work/mvn.log` reports nine tests: `SampleTest` (1), `UserControllerTest` (6), `RoleTest` (1), and `UserTest` (1). The log does not identify its originating CI/Jenkins run.

Both platforms invoke the same build script and Ansible playbook and have reported successful deployments and intentional-failure/same-app recovery. This is the recorded evidence for the Definition of Done flow and recovery criteria. It does not claim end-to-end platform parity: Maven is not explicitly pinned; runners and installed tools may differ; AWS credentials and triggers differ; a prior Jenkins run reported an `INSTANCE_ID` first-build failure while the eighth-test Build #1 outcome is unknown; and target application/database state can affect playbook outcomes. Jenkins Build #3 used the same WAR before and after rescue and only one boot is recorded, so different-release rollback is not demonstrated. These are documented technical limits, not additional Definition of Done blockers.
